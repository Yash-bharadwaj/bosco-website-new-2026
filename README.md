# Bosco Dance Company website

*Where Entertainment Meets Elegance* · **boscodancecompany.com**

A one-page, booking-first site for **Bosco Dance Company**, founded by **Bosco David** in Hyderabad in 2006. Visitors see the work, get to know Bosco, and tap **Plan my event** to open WhatsApp (**+91 99122 51142**) with their details already filled in.

Plain HTML, CSS and JavaScript. No framework, no build step, no backend. Light theme by default with a dark toggle.

## Folders

| Path | What it is |
|---|---|
| `site/` | **The website.** This folder is what gets deployed. |
| `site/index.html` | Page markup and most of the copy |
| `site/js/data.js` | Video cards, showcase, services, FAQ, partners and enquiry form options |
| `site/js/main.js` | All interactions (videos, carousels, film player, enquiry form, theme) |
| `site/js/media.js` | Generated by the media script. Don't edit by hand |
| `site/media/` | Web-ready videos, posters and photos (~121 MB, largest file 16 MB) |
| `site/_headers` | Cloudflare cache and security headers |
| `site/404.html`, `robots.txt`, `sitemap.xml` | Not-found page and search engine files |
| `tools/serve.py` | Local server that supports video seeking |
| `tools/build_media.py` | Turns source videos and photos into the files in `site/media/` |
| `Logo.png` | Source logo for the logo, favicon and share-image builds |
| `raw/` | Source videos, photos and planning notes. **Local only, not in git** |

## Run it locally

```bash
python3 -I tools/serve.py 4174
```

Then open http://127.0.0.1:4174. Python's plain `http.server` can't seek inside videos, so use this one.

## Deploy on Cloudflare Pages

1. In the Cloudflare dashboard, go to **Workers & Pages**, create a **Pages** project and connect it to this GitHub repo.
2. Build settings: framework preset **None**, build command **empty**, build output directory **`site`**.
3. Deploy. Every push to `main` redeploys automatically, and pull requests get preview links.
4. Under **Custom domains**, add `boscodancecompany.com` and `www.boscodancecompany.com`. The domain's DNS is on Netlify today, so add the domain to Cloudflare and switch the nameservers at the registrar to Cloudflare's. An apex domain on Pages needs Cloudflare DNS.

Good to know:
- `site/_headers` caches CSS and JS for a year (their URLs change with every version) and media for a week. HTML is always revalidated, so a new deploy shows up straight away.
- Unknown URLs get `404.html` with a real 404 status.
- Every file is under Cloudflare's 25 MB per-file limit.

## Making changes

- **Copy:** edit `site/index.html` or `site/js/data.js`.
- **After editing any CSS or JS file**, bump the `?v=` value on the four asset links at the top and bottom of `site/index.html` (for example `?v=20261113d` → `?v=20261120a`). Otherwise visitors keep the old cached file.
- **Rebuilding media** (needs `ffmpeg` with SVT-AV1 and `cwebp`):

  ```bash
  python3 -I tools/build_media.py --src . --only vision     # raw/bosco-vision/*.mp4 → "Bosco's vision" loop (AV1 + H.264)
  python3 -I tools/build_media.py --src . --only showcase   # raw/showcase/*.mp4 → "Some of our best work" carousel + js/media.js
  python3 -I tools/build_media.py --src . --only bosco      # raw/boscocheorgraphy…mp4 → "Bosco at work" card
  python3 -I tools/build_media.py --src . --only process    # "How it works" step loops
  python3 -I tools/build_media.py --src . --only logo       # Logo.png → logos, favicons, share image
  python3 -I tools/build_media.py --src . --only awards     # raw/awards/*.jpeg → "On stage at the awards" photo row
  ```

  The video cards and showreel were built from the original Drive downloads (`--src <folder>`; the layout is described at the top of the script). They don't need rebuilding unless a video changes.
- **Adding a video card:** add it to `CARDS` in `tools/build_media.py` and to `works` in `site/js/data.js`.
- **Adding an award photo:** drop it in `raw/awards/`, add it to `AWARD_PHOTOS` in the build script, run `--only awards`, then add a `<li>` to the "On stage at the awards" row in `site/index.html`.
- **Enquiry popup:** a short form (what, date, city, name) opens once after 15 seconds on the page and sends a prefilled WhatsApp message. It waits while a video or the full form is open, rests for 3 days after "Not now", and never comes back once someone has sent an enquiry. The timing and options are in `enquiry.quick` in `site/js/data.js`.
- **Floating buttons:** Instagram (@bosco_daboo) sits above the WhatsApp button on desktop and next to "Plan my event" in the phone bar.
- **Link preview:** the WhatsApp/social preview image is `site/media/brand/company/og-image.jpg` (1200×630). WhatsApp caches previews hard, so if you change the image, give it a new file name and update the `og:image` and `twitter:image` tags.

## Notes on the media

- The BDC logo watermark is a CSS overlay on the videos, not baked into the files. The showcase reels already carry the BOSCO logo, so they skip it (`wm: false`).
- Videos with another company's watermark (ECDC) are left off the site rather than cropped.
- The "Bosco's vision" clip is a 640×360 source. Swap in the HD original when you have it and rerun `--only vision`.
- Videos use AV1 where the browser supports it and fall back to H.264 everywhere else.
