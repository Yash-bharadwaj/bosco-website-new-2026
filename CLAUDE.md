# Bosco Dance Company website: project notes

One-page, booking-first site for Bosco Dance Company (founder **Bosco David**, Hyderabad, since 2006, 3,000+ shows). Built by Yashwanth Bharadwaj, who also built boscodancefoundation.in. See README.md for folders, local run, media rebuilds and deploy.

## Facts and people
- The client is **Bosco David**. He is a different person from Bollywood choreographer Bosco Martis: never use Martis facts, films or photos, and never mention him on the site. Always write "Bosco David" in full.
- Tagline: "Where Entertainment Meets Elegance". Enquiry WhatsApp: 919912251142. Instagram @bosco_daboo ("Bosco Daboo" is his handle; the page shows "Bosco David").
- Never invent facts. Directory-only phones, emails and addresses must never be published. Keep couples' and brides' names off the site.
- The original planning notes (script, content JSON, open questions) are in `raw/planning/`, local only and superseded by the live copy in `site/`.

## Copy
- Plain, natural, short sentences. No slogans or marketing phrasing. Sentence-case titles. No unnecessary em dashes (number ranges are fine).
- The copy lives in `site/index.html` and `site/js/data.js`.

## Build and deploy
- Static site in `site/`, no build step. Hosted on **Cloudflare Pages** (output dir `site`, no build command). Cache and security headers are in `site/_headers`, and the not-found page is `site/404.html`.
- After editing `site/css/styles.css` or `site/js/*.js`, bump the `?v=` string on their four links in `site/index.html`. CSS and JS are cached for a year, so without a new `?v=` visitors keep the old file.
- Media is generated by `tools/build_media.py` into `site/media/`. Never hand-edit media, and never crop a watermark out to hide it: leave watermarked (e.g. ECDC) videos out instead. Source files live in `raw/` (git-ignored); never commit raw files.
- Keep every file under 25 MB (Cloudflare's per-file limit).
- Use `tools/serve.py` locally. Plain `http.server` has no Range support, so videos can't seek.
- Before a push, check that every file referenced from HTML, CSS and JS exists, that nothing in `site/media` is unused, and that there are no console errors at desktop, 375×812 and 812×375.

## Page
- Section order: hero → our work (video cards) → meet Bosco + stats + dancers → Bosco’s vision → some of our best work (showcase coverflow) → recognition (award cards + "On stage at the awards" photo row) → event teams we work with (name marquee; logos later) → services → how it works → FAQ → final CTA → contact.
- Light theme is the default (no automatic switch to dark from the system preference); dark is a toggle.
- Enquiries go only to WhatsApp via `wa.me` with a prefilled message. No backend. Both forms (the full "Plan your event" sheet and the 15-second popup) go through `openWhatsApp()` and `buildMessage()` in main.js.
- The popup must stay polite: once per visit at most, never over another dialog, 3-day rest after "Not now" (`localStorage bdc-quick` = timestamp), never again after an enquiry is sent (`bdc-quick` = "sent"). Don't autofocus its inputs (phones would pop the keyboard).
- Award facts come only from what the photos and certificates show (raw/awards/). Don't add categories that aren't readable on them.

## Rules learned the hard way
- Mobile (check 375×812 portrait and 812×375 landscape): every tap target ≥ 44px (small text links get an invisible `::after` hit area); no horizontal overflow; the film player shows a "turn your phone" hint for landscape videos in portrait and switches to a side caption column when the phone is sideways. On touch devices the enquiry form opens WhatsApp with `location.href` (works in Instagram's in-app browser); on desktop it opens one new tab. Re-check both orientations after any change to the film player or form.
- Watermarks use the `.wm` class. Never let a broad `img { width:100% }` rule reach a `.wm`; scope media rules with `>` or a class. Videos that already carry the BOSCO logo (the showcase reels) set `wm: false`.
- The full-screen player borrows the inline `<video>` that's already playing (showcase slide, Bosco's vision) with `lend()` and returns it with `giveBack()` on close, so it never downloads the file twice. Any code that plays or pauses inline videos must skip a lent one (`isLent(v)`) and cope with a slide whose video is missing while it's lent.
- The loading facts (`D.facts`) may only use facts already on the site. No em dashes.
- Cloudflare Pages doesn't serve byte ranges (206). Moving `site/media` to R2 and setting `config.mediaBase` is the fix for slow mobile video starts.
- Videos ship as AV1 (picked when `canPlayType` says "probably") with an H.264 fallback, both `+faststart`, with short fades at the loop point.
- Drive's anonymous download quota runs out easily: download each raw file once and process it locally.
- Don't download videos from YouTube or Instagram. Ask the owner for the file.
